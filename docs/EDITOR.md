# Native Gogo editor workflow

Enable the Estragon plugin in a Godot project containing the addon. For a direct Yarn install, enable `res://node_modules/@papercraftgames/estragon/addons/estragon/editor/plugin.cfg` in `[editor_plugins] enabled=PackedStringArray(...)` in `project.godot`. Keep the addon inside `node_modules`; no copy, symlink or `.gdignore` over the package is needed. Dependency installation alone does not enable a Godot plugin. See [packaging](PACKAGING.md).

Author GDScript-first `.gogo` files and run scenes normally. Save and both main/current Play paths compile with Godot alone; normal editing needs no Node/Bun executable, external compiler or language server. `gogo.config.json` source roots are authoritative; otherwise discovery uses the documented project exclusions.

## Create a script

Use **Project > Tools > New Gogo Script…**. Godot 4.7 uses `EditorFileDialog`; 4.0 registers that class as abstract, so a capability-checked public `FileDialog` provides the native save workflow there. Choose a project directory and filename, then the Node2D or Node3D starter. Both templates import the composition `Element` and a native layout entry; Node2D includes a text greeting. Imports are computed relative to the generated `.gd` directory and the actual installed resources, including direct Yarn and relocated addons. Attach the generated script to a matching native host to run it.

The dialog appends `.gogo` when no extension is supplied. It rejects another extension, existing files/directories, missing directories, unsafe/excluded paths and locations outside configured source roots. It never overwrites source; cancel writes nothing. Godot 4.0 FileDialog lacks the overwrite-warning toggle: confirming its native warning still leads to Estragon’s refusal, without modifying the existing file. Fix invalid configuration or choose an eligible directory before creating a file. The addon scans the filesystem and opens the new source in the stock Script Editor.

## Highlighting and completion

Authenticated Gogo tabs use theme colors for GDScript keywords/types, annotations, functions, numbers, strings/comments and symbols, plus GGX tags, attributes and embedded expressions. A tolerant line cache carries multiline string/comment/tag/expression state, rescanning the changed suffix. Incomplete code remains editable without a successful compile. Quoted markup and `<` comparisons remain code/string contexts. Undo, redo and buffer replacement invalidate the cache.

Use Godot's completion shortcut (**Ctrl+Space** in the default Linux keymap) or type a member dot, tag opener, annotation or identifier. Suggestions appear in the native CodeEdit popup; native selection, insertion and undo/redo apply. Coverage includes keywords, annotations, declarations, known native/global classes, imported constructible Node aliases, closing tags, writable native/lexical attributes and signals, `key`, supported bool `bind:value`, `self` and explicitly typed members, including inside GGX expressions. Closing-tag candidates include `/` because native CodeEdit treats it as part of the replacement word. Comments, strings and plain markup text do not request code suggestions.

Completion reads ClassDB and lexical declarations/imports; it never instantiates authored scripts. It refreshes for buffer, import/filesystem, source-path and scene-context changes. This is bounded static assistance, not GDScript language-server parity: unknown receivers, arbitrary return-type inference, dynamic collections and complex nested scopes have no promised member inference. Native built-in value types do not expose ClassDB member metadata; their names use native Variant IDs and the compiler’s existing compatible type-name map. Unknown information must not invent members. Ordinary `.gd` tabs retain their native services.

## Diagnostics, save and Play

After a short idle, lightweight native parser/bindable analysis marks authored source lines with a dedicated **!** gutter. The Gogo bottom panel labels this **syntax-only typing feedback**, separate from verified build/semantic validation. Click a panel diagnostic or gutter marker to navigate to its authored `.gogo` line/column; UTF-16 compiler columns are converted to Godot Unicode caret columns. Repair clears the markers. No debugger breakpoints or unrelated editor marks are changed. Godot 4.0's public API does not expose arbitrary language-service squiggles on a stock CodeEdit, so the visible line gutter is the supported presentation.

The plugin saves current Gogo buffers before both Play paths even with native autosave disabled. Unsavable files, syntax/type/handler failures block stale execution and retain authored diagnostic messages. Staged multi-file publication validates actual-path semantics, generated code/maps and dependent resources, refreshes existing Scripts in place and restores bytes/maps/timestamps/cache identity on failure. Repair recovers normal Play. Stable UIDs and no-op output identity are preserved. F04 uses one description compiler for all GGX; retired Node-returning view declarations are rejected. See [cutover](F04_CUTOVER.md).

## Native API boundaries and lifecycle

The public ScriptEditor API on 4.0 has no TextFile-opening entry point. Creation/navigation therefore use a bounded bridge: FileSystemDock selects an exact full path, then the selected public Tree/ItemList emits its native activation signal. No private editor method, guessed basename or menu injection is used. This bridge is version-bounded to Godot 4.0–4.7, with fresh evidence only on the two approved engines; unknown newer versions select the file without pretending to open it. The preexisting owner-accepted hidden never-associated tab limitation [#44](https://github.com/papercraftgames/Estragon/issues/44) remains: reveal and activate that tab to authenticate it. No fix/PASS claim is made for that case.

Godot 4.0 clones highlighters without constructor arguments; authentication explicitly restores their EditorSettings reference so theme changes work there too.

Disable removes the tool action/dialogs, completion handlers and owned gutters, restoring each CodeEdit's prior completion settings. Multiple visible/previously associated Gogo tabs and project restart are covered by focused editor tests. The text-file extension preference is global and persists after disabling; preserve existing values and never erase user preferences.

Native GGX builds at startup before scene restoration. Isolated preflight is unavailable on 4.0.4; mandatory actual-path validation and rollback remain. Running-app hot reload/new inherited defaults are not promised. Live preview and debugger remapping remain future work.

## Focused verification

`tools/check-editor-ux.ts` packs exact tracked addon bytes, installs with Yarn directly into a fresh isolated project and drives the real stock editor/menu/dialog/CodeEdit and main/current child games. It checks completion insertion/undo/redo, highlighting, diagnostics, ordinary `.gd` isolation, plugin lifecycle/restart, rejected creation and failed-Play identity preservation. Two additional template-only path probes cover ordinary `addons/estragon` and a nonstandard location; these are not repeated editor certification suites. Package bytes/UIDs must remain unchanged.

The opt-in **Focused Gogo editor UX** workflow runs Linux 4.7 development checks or bounded 4.0.4/4.7 acceptance by explicit PR label. It does not expand routine CI or the seven-stage release gate. Software OpenGL/Xvfb supplies the editor display; Mesa software Vulkan satisfies stock 4.7's startup RenderingDevice capability probe even under OpenGL. Native errors fail the run; only expected failed-build callbacks and the exact native save-error message inside marked unsavable-source negative cases are accepted. Exact results, screenshots, source/engine hashes and manual-interactive smoke status belong to [#115](https://github.com/papercraftgames/Estragon/issues/115)/its sole PR. Physical keypress tests are not required. Tests use isolated settings and never enable the addon or change preferences in this checkout. See [testing](TESTING.md) and [CI budget](CI_PERFORMANCE.md).

## E03: discover components and accept imports

In a blank Gogo screen, type `extends Node2D` and `func build_view() -> Element:`, then request completion after `<Ent`, `<VB` or `<Te`. The popup identifies the installed **Entry2D**, **VBox** and **Text — EstragonText (native widget)** resources. Accepting a framework candidate inserts its explicit `const … = preload(…)`; an unbound `Element` return annotation receives the composition import too. The original source is not saved during completion. Save/Play still performs the existing authoritative semantic transaction.

The installed catalog contains `Text`, `Rect`, `UiButton`, `VBox`, `HBox`, `Entry2D`, `Entry3D`, and `Element` as a code type. Entries/widgets are suggested for the known host dimension; explicit custom Node preloads and real Godot Nodes remain supported. Resource/model types are never GGX tags. **Button remains Godot Button**; `UiButton` explicitly imports EstragonButton. These friendly aliases are source declarations, not compiler/runtime remapping. The popup shows canonical identity/origin, reuses a manually declared alias for the same resource, and chooses a stable canonical/suffixed name on collision without replacing authored declarations. Ctrl-click/symbol lookup on an imported alias opens its actual resource path.

Paths are calculated with the compiler's existing Source/Build helpers from the actual generated `.gd` directory to the installed Script resource. No addon, node_modules or project root is assumed. Listing, filtering, requesting or cancelling a popup inserts nothing. Acceptance synchronously groups token replacement and imports with public TextEdit complex operations; native undo/redo restores the edit and caret. Single selected prefixes are supported. The adapter handles one caret; multi-caret confirmation is conservatively cancelled instead of applying a plan in unrelated contexts. It does not perform general native GDScript snippet/auto-brace synthesis. All popup navigation and confirmation gestures use Godot's normal key bindings and mouse handling.

The documented `CodeEdit._confirm_code_completion` virtual is implemented by a tiny tool script attached only to otherwise scriptless, authenticated Gogo CodeEdits. An existing third-party CodeEdit script is preserved; import-bearing suggestions are suppressed there. **Project > Tools > Add Missing Gogo Imports** is an explicit, undoable repair for unbound catalog tags and an `Element` annotation, including already typed code. It never guesses imports for arbitrary unknown names or replaces a collision. It is also the safe alternative when another editor plugin owns acceptance. Disabling/closing removes owned callbacks, hints, lookup behavior and adapter script; `.gd` editing remains native and unchanged.

Resource completion is restricted to string arguments of `preload`/`load` and script `extends` contexts. It lists existing project resources using ResourceLoader-recognized extensions and existing directories; relative paths resolve from the emitted output directory. User/absolute external paths and hidden entries are excluded. Symlink detection uses the public DirAccess capability where available; 4.0 lacks it, so only resource-namespace containment and hidden-path checks can be asserted there. Ordinary strings/comments do not receive resources or tags. Directory listing is bounded to the current segment, not a project-wide scan per keystroke.

## Native reuse and verified API boundaries

The integration does **not delegate Gogo buffers to Godot's GDScript completion analyzer**. The public CodeEdit popup and acceptance virtual are presentation/editing APIs. ScriptLanguageExtension's `_complete_code` is an extension-author protocol, not a callable service for the builtin GDScript language. The bound API inventory is recorded in the focused run artifacts; no private analyzer method, external compiler or LSP is called. [Public CodeEdit API](https://docs.godotengine.org/en/4.0/classes/class_codeedit.html), [public Script metadata](https://docs.godotengine.org/en/4.0/classes/class_script.html), [upstream ScriptLanguage API](https://github.com/godotengine/godot/blob/4.7/core/object/script_language.cpp).

| Capability | Official 4.0.4 | Pinned 4.7.0 | Gogo behavior |
| --- | --- | --- | --- |
| CodeEdit popup, keyboard/mouse selection and public acceptance virtual | Supported | Supported | Synchronous explicit imports and one undo group; no delayed text mutation |
| Builtin GDScript completion analyzer as a public callable service | Unavailable | Unavailable | Bounded lexical/ClassDB/live-source adapter; no native analyzer parity claim |
| GDScript-specific native syntax highlighter | Not publicly constructible | Publicly constructible | 4.7 uses the documented GDScriptSyntaxHighlighter on a same-column text carrier; GGX is masked/overlaid. 4.0 retains the tolerant shared-lexer fallback |
| Native class/property/method/signal metadata and builtin type names | Supported | Supported | ClassDB supplies engine metadata; the existing compiler map names native Variant IDs on both engines; native callable signatures use CodeEdit's public hint API |
| Already-cached Script property/method metadata | Supported | Supported | Read text-identical already-held Scripts (and public cached-reference API where present); unsaved Gogo declarations take precedence; no authored `new`, reload or load |
| GDScript builtin value-method/global-function analyzer introspection | Not exposed as a service | Not exposed as a service | No invented String/collection inference or full free-function catalog |
| Existing resource/path metadata | Supported | Supported | ResourceLoader extensions and bounded safe directory listing, not arbitrary string completion |

The [native GDScript highlighter](https://github.com/godotengine/godot/blob/4.7/modules/gdscript/doc_classes/GDScriptSyntaxHighlighter.xml) is capability-checked through public ClassDB APIs, so 4.0 never references an unavailable constructor (its runtime class exists but is not publicly constructible). It sees code with GGX spans masked while retaining code-point columns/newlines, then the shared context adapter overlays tags, attributes, GGX comments and `@bindable`. A text carrier is not compiled, saved or added to an authored scene. It is freed with the highlighter. Normal native GDScript theme rules apply where the native backend exists; the fallback uses EditorSettings colors.

Live Gogo buffers, including other authenticated tabs, provide imports, typed declarations and signals even before a successful build. Saved/cached native script metadata is reused only when its source text matches: 4.0 borrows already-held ScriptEditor/catalog references, and engines exposing ResourceLoader.get_cached_ref can borrow that reference too. Completion never calls ResourceLoader.load for authored code, initializes user Nodes or runs user constructors. ClassDB signatures provide useful native call hints; arbitrary expression return inference, complex nested-scope analysis, inherited new-field running-app initialization and complete GDScript language-server parity remain outside this bounded adapter. Cache invalidation covers edits, source path/import/filesystem and scene changes; reopen and addon reload rebuild catalog/model state.

A measured stock 4.7 gutter issue affects short tabs: `TextEdit::Text::remove_gutter` checks the gutter index against text-line count. Estragon inserts its named gutter at index zero (also a supported 4.0 operation), so removal stays valid for empty/single-line buffers without clearing undo, padding source or suppressing errors. [Upstream implementation](https://github.com/godotengine/godot/blob/4.7/scene/gui/text_edit.cpp#L581). The accepted #44 hidden never-associated-tab boundary remains unchanged.

Focused E03 evidence extends the existing editor-UX runner: a direct Yarn blank first screen, real popup acceptance/imports/undo, keyboard selection, aliases/collisions, live typed sources, resource paths, API inventories, actual attached main/current game execution and a rendered text frame. Standard/nonstandard locations receive only bounded import-path compile/load probes. Exact source/engine hashes, errors, timing, captures and manual-interactive status are on [#121](https://github.com/papercraftgames/Estragon/issues/121)/its sole PR. Routine CI and the P04 release workflow are separate and unchanged.
